# 정책 — 범위 · 경계 · 예산 · 임계치 · 트리거 · 위임

> **사람이 정하는 수치(경계·예산·임계치·트리거·위임)의 정본은 이 파일이다.** 방법론 문서의 수치는 초기값의 설명이다.
> **엔진이 읽는 기계 값**(수집·상관·마이닝·맥락)은 `atlas.toml` 이다. 같은 값을 두 곳에 쓰지 않는다 — 여기서는 `atlas.toml` 의 키로 가리킨다.

## 3. 단계적 가동 (P9)

| 장치 | 켜는 조건 |
|---|---|
| U1 트리아지 + 예측 기록, 수확(`atlas harvest` · 정기 실행 `atlas schedule`), 재빌드, 일일 표집 | 트랙 A 시작부터 |
| 쓰임 기록 — 훅 · 맥락이 낸 제안(`atlas usage`) | 트랙 A 시작부터(`[usage] record`, 기록만 — 관측이 아니다) |
| 보류군 — 훅의 동반 변경 후보를 일부 세션에서 알리지 않음(`[usage] holdout`, 예: 0.2) | 훅을 켠 뒤, 훅이 행동을 바꾸는지 판단할 때까지. 세션 단위 배정 · 상한 0.5 · 세션을 모르는 호출은 보류하지 않는다. 결함이 몰린 파일 경고는 보류하지 않는다 |
| 결정론 소비 — 맥락(`atlas context`)·훅·업무 지도 | 트랙 A 시작부터. 단 `atlas eval` 로 **이 저장소에서** 기준선보다 나은 것이 확인된 기능만 켠다 |
| 일치도·재주석·도출 안정성 **게이트** | 세대 2개 이상 + 확정 WU 100건 이상. 그 전엔 계기판(보고만) |
| 수신함 | 처음부터 (주간 확인 질문으로 소화) |
| 오버레이 | 세대 2개 이상 |
| 소스 확장, 골든셋 40~50건, 격리 독립 도출 3~5회, 나머지 패싯 | 트랙 A 판정(사람 판정 20건 이상, `atlas score`) 통과 후 |
| U2~U5 의 의미 층(원형 카드 주입 등) | U1 예측 적중률이 기준(§7) 이상 |
| 업무 카테고리(업무 지도 · 안내서 · 맥락 줄) | 트랙 A 시작부터. 기본 축(컴포넌트 → 유형)으로 먼저 보고, 미분류 비율(§7)과 사람이 읽은 느낌으로 `method/categories.yaml` 을 다듬는다 |
| LLM 작업 — 카테고리 해설 · 주간 요약 · 이름 제안 · 작업 기록 초안 | 백엔드 승인(§1) 뒤. 사람 판정(`atlas record llm-feedback`)이 쌓이기 전에는 `[llm] auto` 를 비우고 손으로 돌린다 |
| LLM 작업 — 주석(`annotate`) | 트랙 A 주석 패싯을 켤 때. 근거 위반율·재주석 불일치율(§7) 게이트를 따른다 |

- **트랙 A 주석 패싯**: 기원·성격·위험 축·결함 유형·규모(codebook `active_from: A`). 결과·후속은 결정론 계산.
- **트랙 A 계기판**: 예측 적중률(사람 판정 기준) · 서열 보정 · 근거 위반율 · 고아 관측 비율 · 패싯 unknown · 잔차율 · 비용. "도움 됨"은 보조.
- **입력 문서 상한**: 사건당 발췌 ______자, 문서당 ______ KB — `atlas render` 의 `--max-excerpt`·`--max-doc-kb` 로 넘긴다(기본 500자·40 KB) `[추정, 1단계에서 정함]`.

## 5. 승격 · 휴면 · 잔차 · 카드 자격

- **원형·어휘 승격**: 서로 다른 WU 3건 이상, 또는 예외 트랙 1건.
- **예외 트랙**: 결정론 신호(장애·롤백·후속 수정·유발 결함·결제 사고)가 있는 고위험 WU. 모든 재도출 표본에 고정 포함, 다수결 면제.
- **재도출 채택**: 격리 독립 실행의 과반에서 재현(예외 트랙 범주는 1회로 충분).
- **휴면**: 18개월 또는 관측된 주기의 1.5배 중 긴 기간 동안 미출현. 로드하지 않지만 재도출 비교에는 포함. 재출현하면 이력과 함께 활성화.
- **잔차**: `fit: weak` 또는 `residual`. 다음 재도출의 1순위 입력.
- **카드 함정 자격**: 결정론 신호가 있는 근거 WU 또는 포스트모템 문서. 그 외는 카드에 싣지 않는다.
- **카드 처리 수 자격**: 같은 원형에서 3건 이상 관측. 결과 연관(깔끔 종료 n/N · 후속 문제 m/N)을 건수와 함께 싣는다. N < 5 면 권장 문구 없이 건수만.
- **카드 항목 정리**: 6개월간 근거가 새로 붙지 않고 조회도 없는 항목은 다음 재빌드에서 뺀다.
- **업무 카테고리 정의**(`method/categories.yaml`): 바꾸는 것은 §10 절차의 방법 변경이다(근거 한 줄 → 다음 빌드가 새 세대). 엔진의 경로 규칙 후보(안내서 색인 `data/reports/guides/README.md` · 카탈로그 · 주간 요약)와 LLM 의 이름 제안(수신함)은 자동으로 적용하지 않는다 — 사람이 골라 옮긴다. 접점은 팀·채널·역할로만 적는다(사람 이름 금지).
- **LLM 해설의 자격**: 근거 검증(사실 id·근거 인용·숫자 출처)을 통과한 것만 채널에 싣는다. 카테고리의 모양(흐름·크기 구간)이 바뀌면 그 해설은 내려가고, 사람이 `wrong` 으로 판정한 해설은 다시 싣지 않는다.

## 6. 주기와 창

| 루프 | 주기 | 사람 시간 |
|---|---|---|
| 사용 | 수시 | 0~1분 |
| 일일 표집 | 하루 1회 | 30초 |
| 수확 | 주 1회 (무인) | 5~10분 |
| 재빌드 | 월 1회 | 15~30분 |
| 재도출 | 분기 1회 + 트리거 (트랙 B부터) | 1~2시간 |

- 열린 창: 종료 후 30일(`atlas.toml` `policy.open_window_days`). 지나면 확정 WU.
- 재빌드 시간 창: 최근 12개월. 프로젝트 국면 전환이 있었으면 전환 이후만.
- 재주석 표본: 재빌드마다 엔진으로 주석한 WU 의 15% — `atlas llm stability annotate --share 0.15`. 표본은 세대마다 바뀌는 결정론 표본이고(같은 세대에서 다시 돌리면 같은 표본), 일치도는 장부와 `atlas llm status` 에 남는다. 재주석 불일치율 = 1 − 일치도.

## 7. 지표 임계치 (게이트는 §3 조건 충족 후에만 판정)

| 지표 | 경고 | 조치 |
|---|---|---|
| U1 원형 예측 적중률 (사람 판정 기준) | < 60% (사람 판정 20건 이상에서) | 용도·트리거 재설계 또는 재도출 |
| 서열 보정 | `high` 적중률 < `medium` (칸마다 10건 이상에서) | 신뢰도 정의·주석 프롬프트 개정 |
| 고아 관측 비율 | `policy.orphan_ratio_max` (기본 0.2) 초과 | 상관 레시피 점검, 키 습관 |
| 패싯별 unknown | > 30% | 소스 추가 검토 또는 패싯 폐기 |
| Krippendorff α (블라인드 골든, 패싯별) | 신뢰구간 상한 < 0.667 | 코드북 항목 개정 후 재코딩 (목표 0.8) |
| 재주석 불일치율 | > 15% | 코드북 경계 강화, 프롬프트 예시 보강 |
| 잔차율 | > 15% | 재도출 조기 실행 |
| 원형 집합 3세대 불변 + 잔차 상승 | — | 고착 의심, 격리 재도출 강제 |
| 기존 라벨 중복도(AMI) | > 0.8 | 이 체계의 추가 가치 재검토, 범위 축소 |
| 오버레이 비율 | 3세대 연속 상승 | 패턴을 코드북·레시피로 흡수 |
| 카드 "도움 됨" | < 60% (피드백 20건 이상에서) | 보조 지표. 적중률과 함께 판단 |
| 근거 위반율 (`atlas validate` 의 `violation_rate`) | > 5% | 주석 프롬프트·코드북 경계 점검 |
| 커밋 이슈 키 커버리지 (`atlas catalog`) | `policy.key_coverage_min` (기본 0.5) 미만 | 브랜치·커밋 제목에 이슈 키를 넣는 습관 제안 — 상관·사후 귀속의 상한이 여기서 정해진다 |
| 마이닝 효용 (`atlas eval`, 시점 3개 이상) | 기준선 대비 유의하게 나은 시점이 절반 미만 | 그 기능을 소비 경로(맥락·훅)에서 끈다. 설정(`mining.*`)을 바꿔 다시 잰다 |
| 소스 신선도 (`atlas catalog`) | 마지막 수집이 `policy.stale_days` (기본 8일) 초과 | 주간 수확이 도는지 점검 |
| Claude Code 기록 최신 세션 | `policy.transcript_stale_days` (기본 20일) 초과 | 수집 주기 점검 — 원천이 30일 뒤 지워진다 |
| 미분류 작업단위 비율 (`atlas catalog`) | `policy.uncategorized_max` (기본 0.3) 초과 | `atlas guide` 색인의 경로 규칙 제안을 검토해 `categories.yaml` 에 옮기거나, 컴포넌트를 다는 습관 제안 |
| LLM 근거 검증 통과율 (`atlas catalog`) | `policy.llm_accept_min` (기본 0.7) 미만 (이번 달 호출 5건 이상에서) | 거절 이유(`atlas llm status`)를 보고 프롬프트(`method/prompts/`)·모델 점검 |
| LLM 해설 사람 판정 — 쓸모 있음 비율 (`atlas catalog`) | `policy.llm_useful_min` (기본 0.6) 미만 (판정 10건 이상에서) | 틀림·쓸모없음 메모로 프롬프트·입력 맥락을 고친다. 나아지지 않으면 그 작업을 `auto` 에서 뺀다 — 통과율보다 이쪽이 효용 지표다 |
| LLM 월 비용 | 월 상한의 `policy.llm_budget_warn` (기본 0.8) | 범위 축소 — 실행당 대상 수, 자동 작업 |
| LLM 재표집 일치도 (`atlas llm stability`, 선택) | 주석 패싯 일치 < 0.8 또는 해설 근거 집합 자카드 < 0.5 `[추정]` | 프롬프트의 경계 보강. 주석이면 재주석 불일치율과 함께 본다 |
| 훅 동반 변경 후보의 반영률 (`atlas usage`, 보류군이 있을 때) | 알림 − 보류 차이의 95% 구간(세션 군집 부트스트랩)이 0 을 넘지 못함 (양쪽 세션 `usage.min_sessions` 기본 20 이상에서) | 훅의 동반 변경 줄 문턱(`context.hook_min_confidence`)·문구를 고치거나 그 줄을 끈다. 보류군이 없으면 반영률은 연관(훅이 맞혔다)이라 이 판단에 쓰지 않는다 |
| 이슈 맥락 '바꿀 가능성이 큰 파일'의 실제 재현율 (`atlas usage`) | 같은 저장소의 `atlas eval` 재현율@10 보다 뚜렷이 낮음 `[추정]` | 실제 일의 문장이 평가 때와 다르다는 뜻 — 이슈 제목·설명 습관, 유사 작업 수를 본다 |
| 결과를 맞추지 못해 만료된 제안 (`atlas usage`) | 기록의 절반 이상 `[추정]` | 세션·이슈가 수집되지 않는다 — `claude_code` · `jira` 소스와 수집 주기 점검 |
| 수확 실패 (`data/state/harvest-last.json` · `atlas doctor`) | 실패가 있음 또는 마지막 수확이 `policy.stale_days` 초과 | 리포트 첫머리의 실패를 고치고 `atlas harvest` 를 다시 돌린다 |
| 진행 중 작업 폴더의 방치 (`atlas work status`) | `active`·`waiting` 인데 `policy.stale_work_days` (기본 30일) 넘게 손대지 않음 | 끝났으면 `atlas work close`, 계속이면 처리에 근황 한 줄. 위생 경고라 맥락 첫 줄에는 넣지 않는다 |

## 8. 재도출 트리거

지표 경고(§7), 프로젝트 국면 전환(개발→라이브, 시즌 구조 도입, 조직·담당 변화), 새 소스 추가, 레시피 대개정, 모델 교체, 분기 도래(트랙 B).

## 9. 위임 수준

| 수준 | 의미 | 기본 조건 |
|---|---|---|
| D0 | 사람 전담 | 혼돈 모드, 대외 약속, 돈과 영속 데이터가 동시에 걸림 |
| D1 | AI 조사·초안 | 난해·복잡 모드 |
| D2 | AI 실행 + 사람 검토 | 명확 모드 + 위험 축 1개 이하 |
| D3 | AI 자율 + 사후 보고 | 명확 + 토일 + 위험 없음 + 되돌리기 쉬움 |

- 승급: 해당 원형에서 AI 수행 연속 5건 무재작업.
- 강등: 사고 1건이면 즉시 한 단계 이상.
- 토일·명확·저위험 조합은 위임보다 자동화를 먼저 검토한다.

## 10. 방법 변경 절차

1. 변경 이유가 되는 지표·사례를 적는다.
2. 코드북·레시피를 고친다. 코드북이면 스키마를 다시 생성한다.
3. 블라인드 골든셋으로 평가한다. 정확도·α가 나빠지지 않아야 한다. 나빠지면 반려하거나 그 대가를 결정기록에 적는다.
4. `DECISIONS.md` 에 한 줄: 날짜 · 무엇을 · 어떤 지표가 · 결과 수치.
5. 다음 재빌드가 새 세대를 만든다. 부분 갱신하지 않는다.

수신함 항목은 주간 확인 질문으로 소화하고, 4주 지나도 처리되지 않으면 수확 리포트에 만료로 적는다 — 지우는 것은 사람이 한다(무인 실행은 지우지 않는다).
